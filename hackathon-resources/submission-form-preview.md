## 3. What You Will Provide

### 3.1 Project name and description

A short, specific name and a description that says who the agent is for, what it does and what it produces.

**Weak:** "An AI agent platform for business."

**Strong:** "An agent that helps operations leads find and resolve conflicting supplier records across three disconnected systems, producing one sourced answer."

---

### 3.2 Track

Select exactly one primary track. It determines the judging panel and the prizes you compete for.

| Track | What You Build |
|---|---|
| **Solving Fragmented Intelligence** | Demonstrate a clever ability to discover and work across fragmented data sources |
| **The Agent That Can Explain Why** | Agents that investigate complex questions across multiple data sources, connect findings, and produce evidence-backed answers or recommendations |
| **Reasoning Architecture** | Demonstrate a novel ability to turn data, knowledge, memory, and reasoning into reliable decisions and actions |
| **Wildcard [Tinkerer]** | Extend an existing project with Zetaris and Meterless; scored on the new work |

You can change your track any time before the deadline from your team workspace. Make sure your README, slide deck and demo all name the same track.

---

---

### 3.4 GitHub repository URL

```text
https://github.com/<username-or-organization>/<repository-name>
```

**Requirements:**

- The repository is **public**, so judges can open it without requesting access
- It contains all source code
- The README covers setup, usage and dependencies
- If your agents run in Google Colab, the Colab links are in the README

**Recommended:**

- A programmatic entry point, such as `run.py` or a `POST /run` endpoint
- At least three sample inputs and their real outputs
- Logs or traces showing how the agent reached its output
- `.env.example` with placeholders only
- A `SAMPLE_MODE=true` fallback

**Do not submit:**

- A private repository
- A local file path or a zip file instead of a repository
- A repository that needs undocumented manual setup
- A repository with committed keys or secrets

### 3.5 Demo video (1–4 minutes)

Show:

1. **The problem** — the user, the track and why it matters
2. **The solution** — what your agent does
3. **The main workflow** — a real run on a real input
4. **Agent behaviour** — how the agents interact, critique or retry
5. **Key features** — what makes the output useful
6. **Zetaris and Meterless** — how they are integrated

**Check before you submit:**

- [ ] 1–4 minutes long
- [ ] Shows the system actually running
- [ ] Audio is clear and screen text is readable
- [ ] No API keys, credentials or sensitive data on screen
- [ ] If shared as a link, it opens in a private browser window without requesting access

---

### 3.6 Slide deck

Your deck must cover:

1. The problem and target users
2. The solution
3. The agent workflow or architecture
4. The technical stack
5. How Zetaris and Meterless were used
6. What was unique about your use of the sponsor technologies
7. Product visuals
8. Future enhancements

Keep it consistent with your repository and demo. Do not claim anything the code does not do.

---

### 3.7 Sponsor technology explanation

Sponsor Tech is worth 10 points.

| Sponsor | What to Explain |
|---|---|
| **Zetaris** | How it is integrated and what role it plays |
| **Meterless** | How it is integrated and what role it plays |
| **Cursor (with Space XAI)** | How you used Cursor during development |
| **NVIDIA** | Where NVIDIA technology contributes to your project, workflow or use case |

Finish with what was unique about your use of the sponsor technologies.

---

### 3.8 Pre-existing components

Declare anything built before the build window opened on **22 October, 00:00 UTC**: product code, prepared data, models or prior prototypes. Pre-existing open-source libraries do not need to be declared.

**Wildcard [Tinkerer]:** describe the state of your project before 22 October, so judges can see clearly what was built during the hackathon. Only the new work is scored.

Work committed before the build window is not eligible unless it is declared.

## 6. Common Mistakes

| Mistake | Fix |
|---|---|
| **Repository is private** | Make it public and test the link while logged out |
| **Roster wrong when the first submission is created** | Confirm the roster first; the team locks at that point |
| **Demo video over 4 minutes** | Cut to the workflow, the sponsor integration and the output |
| **Video link needs permission** | Set access so anyone with the link can view |
| **No slide deck** | It is a required component |
| **Sponsor explanation is one line** | Explain the role of each sponsor technology and what was unique |
| **Pre-existing work not declared** | Declare it in the form |
| **Keys in the repository** | Rotate them, remove them from history, use `.env.example` |
| **Submitting at 23:44** | Submit with hours to spare |
